大家好，我是陌晨。

9 月 2 日，腾讯 WorkBuddy 开放平台上线了。

Buddy 应用、专家 Agent、Skill、连接器、硬件接入，五种能力一起放出来，阵仗挺大。

普通 AI 学习者可以先忽略那些宏大的生态故事，从一个很小的动作开始。

**把自己已经会做的一件事，封装成 Skill，传上去。**

这件事比继续收藏一百条提示词有用。提示词通常只在自己的对话框里生效，Skill 会把输入、步骤、参考资料和输出要求固定下来，换个任务、换个 Agent，依然可以重复调用。

先把这一步跑通，你才算真正摸到 Agent 的工作方式。

## WorkBuddy 开放的五种能力，分别能干什么

平台这次开放了五个入口，我用普通人能听懂的话解释一下。

**Buddy 应用**，适合把金融、法律、教育、设计这类完整业务封装成一个垂直 Agent。它可以配置系统提示词、工具、模型和具体场景，最后交付的是一个带品牌的应用。

**专家 Agent**，负责封装一个角色的专业知识和工作流程。你可以做单个专家，也可以让多个专家组成团队，各自处理不同环节。

**Skill**，负责教 Agent 怎样完成一件具体的事。写公众号、分析广告、整理会议纪要、生成视频提示词，都能做成 Skill。

**连接器**，负责让 Agent 接触外部系统。平台资料显示，目前支持 MCP 加 Skill、CLI 加 Skill 两种方式，可以继续连接邮箱、文档、数据库和 GitHub 等服务。

**硬件接入**，面向录音笔、眼镜、相机等设备厂商，通过接口把采集到的声音和画面交给 WorkBuddy 处理。

这五种能力由小到大，刚开始学习 Agent，Skill 最适合作为第一站。它不要求你先做完整产品，也不用一上来处理授权、接口和服务器。一个写清楚的 `SKILL.md`，已经能跑起来。

## 第一步，注册并完成认证

进入 WorkBuddy 开放平台后，需要先完成实名认证。

个人认证可以先上传 Skill、连接器和专家。Buddy 应用与硬件接入需要企业认证。没有公司的话，先做个人认证就行，后面仍可继续补企业认证。

平台能力和认证规则可能调整，实际权限以你登录后台后看到的页面为准。

![QQ_1788432435088](media/6f00ea30dd7aed7ed71a.webp)

## 第二步，挑一个已经跑通过的任务

别急着做一个无所不能的万能 Skill。

先找一件你已经反复做过的小事。输入是什么，最后要交付什么，中间有哪些固定步骤，哪些情况必须停下来问人，把这些问题想清楚。

例如视频提示词 Skill，可以规定用户需要提供产品、受众、画面比例和时长，输出必须包含镜头、动作、光线与负面约束。范围越清楚，Agent 越不容易自由发挥到外太空。

**Skill 的价值不在字多，而在每一步都能执行和检查。**



## 第三步，准备 Skill 文件

最小版本只需要一个 `SKILL.md`。补充规则可以放进 `references`，自动处理数据再写 `scripts`。固定的交付格式则放进 `templates`。

```text
skills/
└── your-skill/
    ├── SKILL.md
    ├── references/
    ├── scripts/
    └── templates/
```

不要为了显得专业，把空文件夹全建一遍。当前任务用不到，就先留空。Skill 能否稳定完成工作，比目录看起来像大项目重要得多。

## 第四步，把 YAML 写对

上传时最容易卡住的是 `SKILL.md` 顶部的 YAML 区域。可以先按下面这个结构准备。

```yaml
---
name: your-skill-name
display_name: 展示名称
display_name_en: English Name
description: 一句话说明它能完成什么
description_zh: 简短中文介绍
description_en: A brief English introduction
category: 后台已有分类
version: 1.0.0
author: your-name
---

# 技能说明

当用户需要完成某项任务时，按以下步骤执行。

1. 读取用户提供的材料
2. 检查必要信息是否完整
3. 按固定流程处理
4. 根据验收标准输出结果
```

这里有几个小坑。

字段名后面的冒号必须跟一个空格，缩进统一使用空格。不要混进中文全角引号，需要引号时使用英文半角格式。顶部和底部的三条短横线也别漏。

正式上传前，可以先让 Codex 或 Claude Code 检查一遍 YAML。让 AI 干这种机械校验，远比让它猜你的格式错误靠谱。

我还建议在本地多跑几次。先给它一份材料完整的正常任务，检查输出能不能稳定复现。随后故意删掉一个关键条件，看它会不会停下来追问。再丢一个明显超出范围的需求，确认它不会什么活都往身上揽。

这一步很容易被跳过。结果就是页面填得挺漂亮，别人第一次调用就翻车。上传平台只负责分发，真正决定 Skill 好不好用的，仍然是你写进去的流程和边界。

## 第五步，上传、补配置、提交审核

进入后台的技能页面，上传准备好的 Skill。系统会自动读取大部分字段，随后还要选择分类、服务类目并上传头像。

分类不一定能精准对应你的 Skill，选最接近实际用途的一项即可。别为了蹭热门类目乱选，审核人员也不是第一天上班。

确认预览、介绍和文件无误后提交审核。公开接入记录里的页面提示约 7 个工作日，具体时间以后台通知为准。审核通过后，用户就能在 WorkBuddy 的技能市场里搜索并调用。

写到这里，这个 Skill 才算有了一个公开入口。

## 接下来怎么学

第一个 Skill 发布以后，别马上冲去做 Buddy 应用。

先观察它在哪些任务里会失败，补充输入条件、边界和验收标准。等它能稳定工作，再给它接 MCP，让它读取真实数据。单个专家处理不过来，再拆成专家团队。

这条顺序很朴素。

**先封装方法，再连接工具，最后组织多个 Agent。**

很多人学 AI，总盯着模型又更新了什么。WorkBuddy 开放平台更值得关注的地方，是它给了一条把个人经验变成公开能力的路径。

你会写提示词，这件事只对自己有用。

你能把方法写成 Skill，让别人稳定调用，这才开始有点意思。
